# GPU

A variant of the [secure](../secure/) pod which gives the `xpra` container access to the GPU,
so that it can use the hardware accelerated video encoders: NVENC, VA-API or oneVPL.

The [pod](./pod.sh) script runs the [secure pod](../secure/pod.sh) with `ACCEL=gpu`,
using the `xpra-gpu` image built by [xpra.sh](./xpra.sh).

## Image

[xpra.sh](./xpra.sh) adds the GPU codecs and drivers to the `xpra` image used by the [split](../split/) pod,
`GPU_CODECS` selects them:
* `nvidia`: NVENC, the driver libraries are provided by the host when the container starts
* `intel`: the VA-API and oneVPL drivers for Intel GPUs
* `mesa`: the VA-API drivers for AMD GPUs, with H.264 and HEVC support from RPM Fusion
* `amd`: AMF, which requires AMD's proprietary encoder library

The default is `nvidia intel mesa`, ie: for Intel GPUs only:
```shell
GPU_CODECS="intel" ./xpra.sh
```

## Devices

`GPU` selects the devices given to the `xpra` container, by default it uses NVIDIA if a CDI specification is found,
or the DRI render nodes otherwise:
* `nvidia`: all the NVIDIA GPUs, using the CDI specification generated by the
  [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/cdi-support.html),
  which also provides the driver libraries matching the host's kernel module:
  ```shell
  sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml
  ```
  SELinux does not allow containers to use the NVIDIA devices unless the `container_use_devices` boolean is enabled,
  which applies to all the containers and all the devices. \
  When it is not enabled, the `xpra` and `xvfb` containers are not confined by SELinux (`--security-opt=label=disable`),
  they must use the same label to share the `XShm` segments.
* `dri`: the render nodes (`/dev/dri/renderD*`), not the display devices,
  the container keeps the supplementary groups of the current user (`--group-add keep-groups`),
  ie: `render` or `video`, which may be needed to access them

## Trade-offs

See also [GPU acceleration and the secure pod](../GPU.md), which compares this variant with the [encoder](../encoder/) variant.

This is less safe than the [encoder](../encoder/) variant:
the `xpra` container, which parses the application's X11 requests and the client connections,
can now reach the GPU kernel driver through its device nodes:
a vulnerability exploited in xpra can be followed by an attack on the driver,
which runs in the host's kernel and is shared with all the other processes using the GPU.

Its [landlock](../../../../docs/Usage/Landlock.md) policy uses the `gpu` flag (`--landlock=strict+gpu`),
which allows access to the GPU devices.
The `xpra` container keeps all the other restrictions of the [secure](../secure/) pod,
and the `app` container does not have access to the GPU.
